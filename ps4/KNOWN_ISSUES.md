# Caliza known issues and risks (AI-assisted)

> **Rebrand note (2026-11-26):** this product is now **Caliza** (repository: <https://github.com/felipebasurto/caliza>), a separate GPL-3.0-or-later product built on the PCSX2 core - no longer branded as a PCSX2 fork variant. Evidence, hashes and commit references dated before the rebrand use the old PS4SX2/PS5SX2 identity and `/data/PCSX2` paths (shown here already renamed where operational); they remain valid historical records. The data root is now `/data/caliza` and the first boot after upgrading copies the user's settings, memory cards, saves, BIOS and patches from the old folder automatically (games and texture packs are read from the old folder in place - nothing is moved or deleted). See `ps4/BRAND.md` for the identity guide.


## Critical/platform

1. **Baseline ELF imports PS5-only JIT shared-memory symbols.** `sceKernelJitCreateSharedMemory` and `sceKernelJitMapSharedMemory` appear as dynamic imports even though direct memory is the default. Candidate removes those references under `ORBIS_PS4`; verify with dynamic import audit.
2. **Executable memory is firmware/loader dependent.** Direct memory mapped/mprotected executable is the chosen path. It must be proven on each supported firmware/homebrew loader. If execution fails but RW memory exists, the PS4 candidate now falls back to interpreters; expect a severe performance cost and validate boot/UI behavior on hardware.
3. **OpenOrbis stubs can overstate available symbols.** Export-index checks are necessary but insufficient; keep an explicit PS5-only denylist.

## Renderer/GPU

1. WSI semaphore destruction is now tracked for the normal single-device flow. A focused review found no reachable concurrent-live-`VkDevice` path in the current PS4/PCSX2 flow, so unkeyed semaphore/queue tracking is latent rather than an active bug; revisit only if a second live device or swapchain becomes possible.
2. One global VideoOut/device/queue/swapchain state assumes sequential frontend/GS use, not concurrent independent swapchains.
3. Acquire can wait indefinitely if VideoOut flip status stops reporting valid state.
4. CPU fallback present path serializes with `vkQueueWaitIdle`; new `[ps4wsi]` telemetry should expose it.
5. Fixed 1920x1080 60 Hz mode only; no 120 Hz frame-generation display mode on PS4.


## Storage correctness hardening status

1. ISO and physical-disc sector reads now propagate device failures instead of returning stale static sector-buffer contents. Physical discs remain unsupported/unreachable on Orbis, but the ISO path is live and now converts corrupt/truncated image reads into retryable errors rather than silent corruption. Retry exhaustion now completes the command with error 0x30 instead of wedging the drive; game-visible error recovery still needs hardware/homebrew validation.
2. Folder-card metadata/index writes now detect open/write/flush/close failures and surface them to console-log analysis as warnings. Save ordering/timestamps can still be incomplete if storage fails; metadata/index writes now use scanner-excluded temporary siblings plus rename; file contents are now fsynced before close/flush completion, but best-effort parent-directory synchronization is attempted after atomic replacement where supported, but real power-loss behavior is still not proven.
3. Folder-card empty files can no longer claim stale shared FAT chains during the bounded flush rebuild. Malformed cards remain best-effort input, not fully benign hostile input.
4. Atomic RAW-to-no-ECC memory-card conversion now resolves symlinks and atomically replaces the target (fixing cross-device/USB redirects), preserves permission bits, and fsyncs the parent directory. Hardlink splitting and extended attributes remain edge cases; redirected cards still need hardware validation.
5. `CDVD_MODE_2448` is now accepted for CDDA reads with a PS2-local staging path; RAWQ trailing subchannel is preserved where present and other sources synthesize it. Savestates taken while a large-mode sector awaited DMA now refetch the sector on load instead of DMA-ing unserialized stale staging, and CD block dumps record the same real-or-synthesized subchannel bytes the game consumed rather than zero padding that round-tripped as fake RAWQ data. `CDVD_MODE_2368` now synthesizes a structurally valid 16-byte raw P/Q suffix (mode-1 position data plus CRC) because the backends transport only the 2352-byte main channel. ISO position/control data was corrected, but pregap/index-0, multi-track cue boundaries, catalog/ISRC modes, and copy-protection-grade subchannel fidelity remain unmodeled and console-unverified.

   CHD subchannel passthrough analysis (2026-11-26, host-side): `ThreadedFileReader::ReadSync` strides sector offsets by the CHD-internal unit size (commonly 2448), not the external block size, so both the 2352 and 2448 probes in `InputIsoFile::Detect` read correctly aligned data and the earlier 2352 probe wins purely by ordering; `CopyBlocks` then crops each unit's 96-byte subchannel tail for the image's lifetime. Enabling passthrough requires probing 2448 first when `InternalBlockSize() >= 2448` AND deciding subcode packing: CHD track metadata subtype RW stores interleaved subcode while RW_RAW stores deinterleaved bytes, and which layout PS2 CDDA software expects in the raw 2448 frame is not documented in-tree and cannot be validated without hardware. Wrong-order subchannel would be worse than the current deterministic synthesis, so passthrough is deferred until hardware or authoritative documentation resolves the layout question; flat RAWQ images already preserve their real trailing subchannel because their detection is unambiguous.


## Input/audio/filesystem

1. Player-1 disconnect stuck-input handling and extra-controller hotplug retry are improved, but the PS4 pad connected-byte layout is unverified; the candidate fails open and logs the byte window for first console validation.
2. USB keyboard/mouse remains off by default on PS4. `/data/caliza/flags/usbkbm` opts in for hardware testing; behavior is still console-unverified.
3. Cover downloads now use the mbedTLS HTTPS client on PS4, but DNS/TLS/redirect behavior is still console-unverified.
4. Pad state/hotkey hardening is improved: foreground-user fallback exists, left/right correctly cancel the filter combo, state requests are queued rather than overwritten, guest power-off is prioritized, and replaced pad objects are retired rather than destroyed under live raw pointers. These paths are compile-validated only and still need hardware testing, especially multitap/recreation behavior and simultaneous hotkey timing. Emulation and frontend shelf audio teardown are now bounded and use-after-free-safe even when sceAudioOutOutput blocks indefinitely, at the cost of a deliberately leaked port in that pathological case; analyzer coverage detects the emulation-side timeout. Analyzer coverage includes the frontend teardown timeout.
5. NFS game shares now use CEMUPS4 `/net/shareN` rather than the PS5 `/nfs` libc-wrap layer. Only plain NFSv3 `nfs://host/export` addresses are supported, behavior is console-unverified, and SMB is not exposed in the UI yet.
6. NVRAM lives beside BIOS; read-only custom BIOS folders can break NVRAM persistence. Writes are now periodic, dirty-only, and atomic on PS4, but a read-only location still cannot persist them.
7. **In-game pause menu awaits real PS4 verification.** The default trigger was moved off Share/Create (which collided with GoldHEN's long-press Share cheat menu and locked up the console) to single-button **Touchpad click** (`Touchpad` + `None`, unused by GoldHEN or PS4 system shortcuts, intercepted before reaching the game so it does not press PS2 Select), remappable to any single button or two-button combo (such as `L3 + R3 + L1`) in Controls and the companion web panel with automatic migration of legacy Share/Create bindings. Pause/resume, 10-slot quick save/load with backup fallback, multi-disc swap, return to library, input-leak gating, and `[pause]` `boot.log` lines are host-tested only and must be verified on real PS4 hardware (see `ps4/CONSOLE-QA.md` QA-4 through QA-10).

## Memory/robustness

1. Savestate loading streams entry payloads, and synchronous saves stream entries without a second full-state buffer; both paths still need console memory/correctness validation. Threaded saves intentionally keep the full-snapshot contract. Corrupted-state handling is now fail-closed for truncated fixed memory entries, negative/overflowing memory reads, oversized VIF staging, impossible GIF queue geometry, and stream-exceeding string/container lengths, excessive HostFS handles, invalid USB packet targets/state/staging sizes, exact GIF packet-span geometry, impossible frozen non-AD GIF tags, and inconsistent OHCI asynchronous packet tuples and their reset-time queue linkage, but legitimate-state compatibility still must be proven on hardware and this is not a complete hostile-input proof.
2. Baseline compiler warnings have been triaged and the highest-confidence correctness issues integrated; remaining warning-volume reduction is non-critical cleanup, not evidence of a clean runtime.
3. The non-executable-memory interpreter fallback is compile-validated only. It should allow boot/UI diagnostics, but its real speed and correctness on Jaguar are unknown.
4. The legacy non-PS4 direct-code fallback still maps `0x33` (CPU/GPU RW, no CPU execute) and lacks ownership tracking. It is PS5-only, was not changed without PS5 hardware validation, and should either use the validated RW-to-mprotect path or fail cleanly in a future narrow patch.
5. JIT shared-memory ownership remains incomplete on the PS5-only opt-in path because the kernel handle is lost; do not reintroduce those imports on PS4.


## Memory-pressure tradeoffs

1. The PS4 MTVU backing is capped at the existing 2048 KiB default lap, removing the ability to test larger 4/8/16 MiB laps on the normal PS4 candidate. This preserves default behavior while avoiding 14 MiB of always-resident BSS, but heavy-MTVU games still need hardware comparison before the cap is treated as final.
2. Folder memory-card superblock geometry is now validated before the implementation trusts it, and direct FAT/data-cluster indexing is bounded. Metadata-cluster traversal is now iterative and cycle-safe, direct FAT-chain indexing is bounded, and directory recursion is depth-capped. Out-of-range sector pages are now rejected before caching. Null host file handles are no longer cached as permanent folder-card failures, stdio buffers are flushed before dirty pages may be dropped, and per-flush visited marks bound shared-directory DAG expansion, and quick-access targets are rebuilt each flush. Close-time metadata write state is now cleared, close failures and close-time pending-write loss are logged/analyzed, shared/cyclic file data chains are bounded during flush rebuilds, memory-card entry names are bounded and slash-containing host-path escapes are sanitized, used-but-unmapped cluster writes are retained/reported, and large host gap fills are chunked. File/folder data contents are now fsynced, and shrunk backing files are truncated and fsynced after index writes, with bounded retry even when dirty pages were already consumed. Load and flush recursion now use the same depth cap, conversion replacement is atomic, and failed uncached reads no longer merge stale staging data. Broader malformed-card behavior still needs review, so malformed metadata must not be treated as fully hardened untrusted input yet.

## User-data layout

1. `OrbisDir()` still uses a flat `/data/caliza` fallback when a subdirectory does not exist. Existing flat installs must not be migrated blindly: memory cards, savestates, BIOS/NVRAM, and custom filenames need a validated one-time migration plan on real hardware. Do not create `memcards/`, `savestates/`, or `bios/` casually on a console with flat user data, or the layout can switch and orphan existing files. The audited design is rename-only, per-category transactional, idempotent after power loss, creates a target directory only when it will receive files, classifies BIOS before `.bin` memory cards, moves BIOS sidecars as families, honors configured custom card names, skips destination collisions, and leaves ambiguous patches/covers/disc images flat. It should be implemented flag-gated off and console-validated before becoming default.
2. Forced interpreter configuration is a runtime execution gate, not a durable user-visible configuration policy. `CHECK_*JITMEM` prevents generated code execution even if settings are later edited, but some non-fatal decisions may still read raw config values; audit them before adding new JIT consumers.

## Experimental features awaiting hardware validation

1. **Smart tune (the per-game graphics auto-tuner) is compile-validated only.** Its measurements are truthful only when the user plays real in-game scenes through the whole pass; menus, loading screens, or paused play make every configuration look fast and produce a wrong winner. The ladder assumes GPU cost rises monotonically with upscale multiplier, prunes at the first failing step, and tests aniso/CAS extras at the winning resolution. It writes only the game's own settings file, restores the original content when even 1x fails, and never touches blending accuracy or per-game hacks. A bad pick is fixed by re-running the row in a heavier scene or by setting Resolution manually. The 30-second lead-in is fixed, there is no mid-tune cancel beyond leaving the game, and a quit mid-tune leaves the last-tested step in the file. PS4 GPU memory limits are not modeled: a high multiplier could fail for memory rather than speed and the tuner cannot tell the difference yet.
